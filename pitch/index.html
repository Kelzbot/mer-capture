The problemMER Capture · 01 / 05

The same encounter is written down three times, by three people, and only the last version counts.

User

Clinicians and health information officers in Nigerian secondary and tertiary facilities.

Current workflow

1 Clinician writes a free-text consultation note → 2 someone re-keys it into the EMR → 3 someone else codes the diagnosis for reporting and billing → 4 the coded record is what reaches health information systems and funders.

Pain point

The same encounter is manually transcribed and re-interpreted three times. Diagnoses go uncoded, SOAP sections go incomplete, and treatment plans get separated from the diagnoses that justify them.

Consequence

Incomplete and inconsistent documentation degrades continuity of care, corrupts facility reporting, and surfaces later as data quality findings that put programme funding at risk.

Problem statement

Clinicians need a better way to convert free-text consultation notes into complete, coded, structured documentation, because manual transcription and coding is repeated, inconsistent and unverifiable, resulting in incomplete records and unreliable facility reporting.
The solutionMER Capture · 02 / 05

MER Capture — one pass from narrative to a coded record the clinician signs.

Input

The free-text narrative — pasted into the review view, or one chosen column of an uploaded CSV / XLSX.

›
De-identify

On this device, before any network call. Labelled IDs, Nigerian phone numbers and labelled or titled names become tokens.

›
AI

Only the de-identified text is sent. Extraction to a fixed JSON schema; every field carries a confidence score and a verbatim source span.

›
Output

Structured SOAP note, ICD-10 code, medications, plan. Quality flags are then computed by rules, not by the model.

›
Human

In the single-note view: edit any field, hover it to highlight its source sentence in the original, sign off by name.

›
Action

The confirmed record downloads as CSV. EMR / FHIR mapping is proposed, not built.

Why AI is justified

The input is unstructured free text carrying clinical abbreviations, dictation artefacts and inconsistent phrasing — rules and keyword search cannot reliably parse it.

Where the human actually sits

The review-and-sign-off gate exists in the single-note view. Batch mode is an analyst path — dataset-wide quality and evaluation — and has no per-record sign-off yet.

The architectural line that matters

The LLM only reads and extracts. Every quality flag and every derived metric is computed by deterministic rules over the extracted fields. No reportable output is ever generated by the model.

Disclosure. The extraction, de-identification and rules engine were originally built for an HIV programme reporting use case and adapted to this track's dataset today. The clinical schema profile, the documentation quality rules and the evaluation harness were built during the event. Gemini 2.5 Flash is a third-party foundation model accessed via API — it is not our model.

Stack. React 19, TypeScript, Tailwind 4, Vite, PapaParse, SheetJS, lucide-react and the Anthropic SDK — all open source. No charting library; the bars are CSS.

Models. No model was trained or fine-tuned. The only AI component is a hosted foundation model called over HTTPS. Two providers are wired up in extract.ts and chosen at runtime: Google gemini-2.5-flash (default) and Anthropic claude-sonnet-4-6. The key is entered in the page, kept in memory, and sent only to the provider you pick.

Prove itMER Capture · 04 / 05

Claim

MER Capture extracts structured clinical fields and ICD-10 codes from free-text consultation notes at a factual-match rate high enough to make clinician review faster than manual documentation, without inventing facts absent from the source.

Test population & setting

Consultation narratives from the organiser dataset. Deployment target: Nigerian secondary and tertiary outpatient clinics.

Ground truth

The reference structured fields paired with each narrative. Extraction sees the narrative alone; only fields with a matching reference column are scored.

Held-out set

{{TEST_SET_SIZE}} records — a seeded shuffle, default 20%, with the seed and set size shown on screen so the split is reproducible and stated. The prompt is fixed in extract.ts and holds no dataset-specific examples.

Definitions, as implemented. Exact — equality after lowercasing, collapsing whitespace and stripping trailing punctuation; macro-averaged across fields, micro also reported. Token F1 — bag-of-words F1 with stopwords removed, so correct content phrased differently still scores. ICD-10 — full code, and separately the 3-character category (J45.9 counts against J45.0). Hallucination — field populated where the reference is empty, over the count of empty references. Omission — field empty where the reference is not, over the count of scored pairs. Negation errors — term-level polarity inversions: a term the reference denies that the extraction asserts, or the reverse. Every number carries its denominator on screen.

Success threshold

≥85% field-level factual match and <2% hallucination rate would justify a supervised clinical pilot.

Failure criteria

Any hallucination rate above 5%, or any negation inversion on a safety-relevant field — allergy, medication, symptom denial — stops deployment pending redesign.

Baseline comparison

Not measured. We have not yet run regex / keyword section-splitting on the same held-out set, so we cannot claim extraction beats the simplest non-AI alternative. That baseline is the next thing we build.

Fairness

Performance should be checked separately across age, sex and presenting condition. Whether the dataset permits this depends on those columns being populated — where they are absent, the subgroup result is reported as unavailable rather than assumed equal.

Real worldMER Capture · 05 / 05

What it takes to run this in a clinic, and what happens when it is wrong.

Deployment context

Browser-based. No server of ours, no GPU. Runs on an ordinary facility laptop. De-identification happens on the device — but the call to the model provider still needs the internet, so this is not an offline tool.

Biggest assumption

That reviewing a pre-filled structured note is meaningfully faster than typing it — and that clinicians will actually correct low-confidence fields rather than rubber-stamp them.

Biggest risk

Automation bias. A confident, fluent, wrong extraction being confirmed without scrutiny.

Safeguards — all of these are in the code

  • Confidence score on every extracted field.
  • Source span on every field, located back in the note — hover a field and the sentence highlights in the original.
  • Named sign-off gate: in the single-note view, export stays disabled until a clinician types their name and ticks the review box. Batch export is not yet gated.
  • Absence is a valid answer — the model is told to omit rather than guess, and empty values are dropped before they reach a field.
  • Deterministic rules for every derived flag and metric — no number on screen is model-generated.
  • De-identification on device before any call, and an inspector showing the exact prompt and payload that left the browser alongside the identifier map that did not.
  • No storage of any kind — no localStorage, no server, nothing survives the tab.

When it is wrong

  • The source span makes the error visible at the point of review.
  • Low confidence is flagged before the clinician signs.
  • The clinician overrides.
  • The confirmed record — not the extraction — is what leaves the system.

Our AI must never

Generate a diagnosis, a code, or a clinical fact that is not present in the source note — or export any record without named clinician confirmation.

Enforced today in the single-note view. Batch mode exports without a per-record gate — closing that is the first thing on the list, and we would not run a pilot until it is closed.
